Case Study

WIMIA — What Is My Itinerary Again?

A web-based event management platform that centralizes itineraries, automates reminders, and streamlines communication for sports organizations — designed and shipped end‑to‑end (UX + full‑stack).

Overview

Context

WIMIA was built to solve a recurring pain point for clinics and events: travel details were scattered across PDFs, chats, and email threads. Coaches, athletes, and admins needed a single source of truth with clear schedules and proactive notifications.

Challenge

Manual itinerary management created duplicated effort and late updates. The core challenge was to reduce operational overhead for admins while giving athletes a fast, reliable way to access their own travel information.

Outcome

The result is a responsive web app where admins can compose event itineraries, attach schedules, and send automated reminders. Athletes receive simplified, personalized views of where to be and when — no hunting through messages.

Engineering

Architecture

WIMIA is a Django‑based web app with a pragmatic monolith architecture. The stack prioritizes reliability, quick iteration, and maintainability for a small team.

Client (Browser)
  └── Responsive UI (HTML/CSS/JS)
      └── Fetch / form posts
Backend (Django)
  ├── URL routing → views (CBV/FBV)
  ├── Templates + context rendering
  ├── ORM models (Events, EventDay, FlightInfo, Assignment, CoachContact)
  ├── Services (email delivery, reminder scheduling, token refresh)
  └── Forms & validation (chunked, progressive)
Persistence (SQLite in dev / Postgres-ready)
  └── Migrations via Django
Integrations
  ├── Gmail OAuth (token refresh automation)
  └── File uploads (schedule PDFs)
Observability
  └── Admin metrics, basic logs, error toasts

Data Model (Key Tables)

  • Event — name, location, dates, level, coach contact, rental car info, alternate travel notes.
  • EventDay — per‑day datetime blocks (supports Day 1, Day 2, ... with add‑a‑day pattern).
  • FlightInfo — unified model for per‑person flights (airline, number, depart/arrive, confirmation, bag options).
  • Assignment — employee ↔ event relationship with role and visibility.
  • ScheduleDocument — file uploads (PDF) with metadata and versioning fields.

Notable Backend Features

  • Automated Token Refresh: Background refresh for Gmail OAuth tokens prevents email delivery failures.
  • Reminder Service: Pre‑event notifications (e.g., T‑7 days, T‑24 hours) using deterministic schedule rules.
  • Composable Forms: Long forms split into digestible sections; server‑side validation mirrors UI hints.
  • Role‑aware Views: Admins see full event context; athletes see only assigned, relevant details.
  • Document Pipeline: Secure PDF upload, storage, and linking per event/day.

Security & Ops

  • CSRF protection and session auth via Django; environment secrets through .env.
  • Field‑level safeguards for PII (coach phone/email) and least‑privilege access for athlete views.
  • Graceful error handling and resilient email retries for transient failures.

# views.py (simplified)
class EventDetailView(LoginRequiredMixin, DetailView):
    model = Event
    template_name = "events/detail.html"

    def get_context_data(self, **kwargs):
        ctx = super().get_context_data(**kwargs)
        event = self.get_object()
        ctx["days"] = event.eventday_set.order_by("start_dt")
        ctx["flights"] = FlightInfo.objects.filter(event=event).select_related("user")
        ctx["pdf"] = event.schedule_document
        return ctx

Why This Matters

The engineering choices support the UX intent: less admin toil, fewer surprises before travel, and a reliable, simple delivery mechanism for time‑sensitive information.

Key Learnings
  • Designing for power vs. casual users requires different defaults and visual weight.
  • Automation reduces cognitive load; reminders are as much a UX feature as a backend feature.
  • Small label and hierarchy tweaks, validated with quick tests, yielded outsized clarity gains.
Impact

WIMIA consolidates itineraries, removes manual comms, and gets athletes the right information faster. Admins save hours per event; athletes gain confidence that their schedule is accurate and accessible.

What’s Next
  • Instrumentation for task‑level metrics (open rates, reminder effectiveness, time‑to‑info).
  • Move to Postgres + task queue for high‑concurrency email and scheduling.
  • Public sharing links with granular expiry and auditing.
